# ЛЦТ 2026. Задача 1 - Платформа подбора роботизированных решений с расчётом экономического эффекта и визуализацией работы роботов на объекте

Go API, React SPA, Postgres 18.

Документация для чтения: каталог `docs/`. Локально: `cd docs && mdbook serve`. mdBook ставится командой `cargo install mdbook` или пакетом системы. Каталог `docs/book/` не коммитят.

## Запуск

```bash
docker compose up --build
```

- UI: http://localhost
- API: http://localhost:8080
- Проверка: http://localhost:8080/health

Порты на хосте меняются через `WEB_PORT` и `API_HOST_PORT`. Миграции применяются при старте API.

Каталог загружается из `data/catalog.csv` только если таблица `solutions` пустая. ТТХ из `data/seeds/robot_specs.json` обновляются при каждом старте API (upsert, без удаления solutions). Строка CSV с повторным id становится отдельным решением (первая строка сохраняет id, остальные получают производный), см. `data/seeds/NOTES.md`. Расчёты читают каталог из базы, поэтому правка в «Админ» попадает в следующий расчёт.

Сброс базы удаляет все проекты, запуски и аккаунты; при следующем старте API заново загрузит каталог и создаст демо-аккаунты:

```bash
docker compose down -v
```

Гость хранит параметры в браузере. Расчёт и экспорт PDF и Excel идут через API без записи коммерческих данных в Postgres и в журналы. Проверка карты и симуляция демо-склада идут в браузере, в ядре WebAssembly, которое отдаёт API (`/api/engine/`).

## Запуски и отчёты

Каждый расчёт экономики и каждая симуляция сохраняют неизменяемый запуск: снимок входов проекта, `input_hash`, контрольную сумму каталога (`catalog_content_sha256`), версии моделей, seed и уровень подтверждённости (предварительный, настроенный, калиброванный, подтверждённый). Список запусков: `GET /api/projects/{id}/runs`, страница "История".

Отчёты PDF и Excel короткие и рассчитаны на человека, который принимает решение. Финансовый отчёт сравнивает базу и варианты: первоначальные вложения, ежегодные затраты, годовой денежный эффект, простую окупаемость и затраты за горизонт, показывает состав лучшего варианта и допущения, которые могут изменить вывод. Лучшим считается вариант с самой короткой простой окупаемостью в пределах горизонта; при равной окупаемости и при окупаемости дольше горизонта отчёт не выделяет ни один вариант и говорит об этом. Отчёт по симуляции даёт вердикт, SLA, производительность, процессы и узкие места. Отчёт строится из снимка запуска, но сам снимок (входы, хэши, seed, версии моделей, карта) остаётся в Postgres и в файлы не попадает. NPV, IRR, дисконтированная окупаемость и денежный поток по годам видны на странице расчёта и в ответе API, в отчёты они не входят. Ответ содержит заголовки `X-Run-Id` и `X-Input-Hash`. Экспорт текущего результата после изменения черновика возвращает 409 `stale_result`, исторический запуск выгружается с пометкой, что черновик изменился.

## Демо-аккаунты

Создаются при старте API, если таких email ещё нет.

| Роль | Email | Пароль |
|---|---|---|
| пользователь | user@demo.local | demo-user |
| администратор | admin@demo.local | demo-admin |

Смените демо-пароли перед любой внешней выкладкой. Снаружи сайт работает только по HTTPS: задайте `COOKIE_SECURE=true` и `PUBLIC_ORIGIN` с адресом сайта.

## Переменные окружения

См. `.env.example`.

| Имя | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения Postgres |
| `API_PORT` | порт API, по умолчанию 8080 |
| `PUBLIC_ORIGIN` | адрес сайта для проверки `Origin` у изменяющих запросов, по умолчанию `http://localhost` |
| `COOKIE_SECURE` | `true` (по умолчанию): cookie `__Host-session` только по HTTPS; `false` только локально, cookie `session` |
| `SESSION_IDLE_HOURS` | сессия без запросов истекает через столько часов, по умолчанию 168 |
| `SESSION_MAX_DAYS` | предельный срок сессии в днях, по умолчанию 30 |
| `CATALOG_CSV` | путь к CSV для первого импорта и админ-обновления |
| `CATALOG_SPECS` | путь к JSON с ТТХ демо-роботов |
| `PGPOOL_MAX_CONNS` | размер пула pgx |
| `BCRYPT_COST` | 10, 11 или 12 |
| `DEMO_USER_EMAIL` | демо-пользователь |
| `DEMO_USER_PASSWORD` | пароль демо-пользователя |
| `DEMO_ADMIN_EMAIL` | демо-администратор |
| `DEMO_ADMIN_PASSWORD` | пароль демо-администратора |
| `SIM_WORKERS` | число воркеров симуляции в процессе API, 1-8, по умолчанию 2 |
| `SIM_JOB_TIMEOUT_MIN` | предел одного задания симуляции в минутах, по умолчанию 10 |
| `SIM_MAX_ACTIVE_PER_USER` | активных заданий симуляции на пользователя, по умолчанию 3 |
| `SIM_LOG_RETENTION_DAYS` | срок хранения журнала событий, по умолчанию 90 |
| `TRASH_RETENTION_DAYS` | сколько дней удалённый проект лежит в корзине, по умолчанию 30 |
| `ENGINE_DIR` | каталог с `engine.wasm` и `wasm_exec.js`, которые API отдаёт браузеру; в образе `/engine` |
| `APP_ENV` | `local` (по умолчанию) открывает `GET /api/dev/outbox` для просмотра писем; в развертывании задайте другое значение |
| `MAIL_MODE` | `capture` (по умолчанию): письма остаются в базе и не уходят наружу; `smtp`: отправка через `SMTP_HOST` |
| `MAIL_FROM` | адрес отправителя писем |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` | SMTP при `MAIL_MODE=smtp`, порт по умолчанию 587 (STARTTLS) |
| `REGISTRATION_MODE` | `open` (по умолчанию) или `invite`: регистрация только по приглашению |

Локально без Docker: Postgres 18, задать `COOKIE_SECURE=false` и `PUBLIC_ORIGIN=http://localhost:5173`, `go run ./cmd/api` в `api/`, `npm run dev` в `web/` (Vite проксирует `/api`, поэтому браузер видит один origin). Браузерное ядро в этом случае нужно собрать самому, иначе проверка карты и Симуляция демо не заработают: `cd api && GOOS=js GOARCH=wasm go build -o <каталог>/engine.wasm ./cmd/engine-wasm`, туда же положить `wasm_exec.js` из `$(go env GOROOT)/lib/wasm/` и задать `ENGINE_DIR=<каталог>`.

## Тесты

```bash
cd api && go test ./...
```

Интеграционные тесты (очередь симуляций, права владельца, гостевой режим, отчёты, миграции на пустой базе вверх и вниз) запускаются, если задан `TEST_DATABASE_URL` (пользователь с правом `CREATE DATABASE`). Каждый тест создаёт и удаляет свою базу.

```bash
docker run -d --name sim-it-pg -e POSTGRES_USER=app -e POSTGRES_PASSWORD=app -p 55432:5432 postgres:18
cd api && TEST_DATABASE_URL="postgres://app:app@localhost:55432/app?sslmode=disable" go test ./...
```

```bash
cd web && npm test && npm run lint && npm run build
```

### E2E

Playwright проверяет основной сценарий, гостевой режим, доступ чужого пользователя, ошибки импорта параметров, отмену и повтор симуляции. Тестам нужен стек на чистой базе. Отдельный проект compose не трогает основной том. `PUBLIC_ORIGIN` должен совпадать с `E2E_BASE_URL`, иначе API отклонит запросы тестов с кодом `csrf`:

```bash
PUBLIC_ORIGIN=http://localhost:8088 WEB_PORT=8088 API_HOST_PORT=18080 docker compose -p mh26e2e up --build -d
```

```bash
cd web && npx playwright install chromium && E2E_BASE_URL=http://localhost:8088 npm run e2e
```

```bash
WEB_PORT=8088 API_HOST_PORT=18080 docker compose -p mh26e2e down -v
```
