# Разработка

Раздел для тех, кто меняет код. Правила оформления кода, комментариев, текста интерфейса и документации собраны в файле `AGENTS.md` в корне репозитория. Ниже описано, где что лежит и что нельзя разъединять.

## Где что лежит

Числа считают пакеты `api/internal/matching`, `api/internal/econ` и `api/internal/sim`. Интерфейс формулы не придумывает. Сборка прогона симуляции из черновика находится в `api/internal/simbuild`: она не обращается к базе, и один и тот же вход уходит в очередь заданий и в браузерное ядро.

| Что | Где |
|---|---|
| Процесс API | `api/cmd/api` |
| Браузерное ядро (WebAssembly) | `api/cmd/engine-wasm`, файлы отдаются с `/api/engine/` |
| Запись проекта операциями | `api/internal/ops` (эталон), `web/src/store` (то же применение на клиенте) |
| HTTP-клиент интерфейса | `web/src/api` |
| Запросы к Postgres | `api/internal/db`, код генерируется sqlc и руками не правится |
| Загрузка каталога | `api/internal/importers` |
| Отчёты | `api/internal/exporters` |
| Очередь симуляций | `api/internal/jobs`, `api/internal/simjobs` |
| Схемы параметров объектов | `api/internal/objects` |
| Контракты данных | `contracts/` |

Запись проекта идёт только операциями: вставка, установка значения, удаление и перемещение. Отдельного метода `PUT` для содержимого проекта нет. Расчёт операцией не является, его считает Go.

## Что нельзя разъединять

- Расчёт при том же снимке, каталоге, версии модели и зерне генератора даёт те же числа. На запуске записывается контрольная сумма каталога. Смена версии экономики или подбора делает сохранённый запуск устаревшим.
- Если симуляция и экономика расходятся больше чем на 15%, в ответе есть флаг проверки. Скрывать его нельзя.
- Коммерческие данные гостя в Postgres не пишутся.
- Загрузка строки каталога идемпотентна по идентификатору решения.
- Версия экономики задана константой `econ.ModelVersion` (сейчас `econ-v3`). В ADR 0004 она ещё названа `econ-v2`, действует константа. Версия событийной симуляции: `sim.Version` (`sim-v2`). Быстрая проверка пропускной способности внутри расчёта остаётся `sim-v1` в `api/internal/sim/geom`.

Контракт HTTP: `api/openapi.yaml`. Почему нет `PUT` и как устроены снимки: [ADR 0001](adr/0001-snapshots-variants-jobs-events.md) и [ADR 0003](adr/0003-operations-and-sync.md).

## Новое поле проекта

Поле начинается в `contracts/ops/project.schema.json`. Затем из корня репозитория выполните:

```bash
node scripts/gen-ops-schema.mjs
```

Скрипт копирует схему к читателям в Go и в `web/src/store` и обновляет сгенерированный TypeScript. Фикстура для поля нужна в `api/internal/ops/fixtures_test.go`. Пока фикстуры нет, поле считается незакрытым.

## Новый маршрут API

Обработчик и правка `api/openapi.yaml` идут в одном изменении. Поля ответа в Markdown не дублируют, их описывает `api/openapi.yaml`.

## Новая переменная окружения

Чтение идёт в `api/internal/config`. Имя и смысл записываются в `.env.example` и в раздел [Переменные окружения](reference/env.md). Секреты в репозиторий не кладут.

## Новая миграция

Новое изменение схемы записывают новым файлом в `api/migrations`. Применённый файл не правят. Если добавляется индекс, причина указывается в имени файла.

## Тесты

Тесты сервера:

```bash
cd api && go test ./...
```

Интеграционные тесты (очередь симуляций, права, гость, отчёты, миграции вверх и вниз) запускаются, если задана переменная `TEST_DATABASE_URL`. Пользователю нужно право `CREATE DATABASE`, каждый тест создаёт и удаляет свою базу:

```bash
docker run -d --name sim-it-pg -e POSTGRES_USER=app -e POSTGRES_PASSWORD=app -p 55432:5432 postgres:18
cd api && TEST_DATABASE_URL="postgres://app:app@localhost:55432/app?sslmode=disable" go test ./...
```

Тесты интерфейса:

```bash
cd web && npm test && npm run lint && npm run build
```

Сквозные тесты Playwright выполняются на чистом стеке Compose. Отдельный проект Compose не трогает основной том. `PUBLIC_ORIGIN` должен совпадать с `E2E_BASE_URL`, иначе API отклонит запросы с кодом `csrf`:

```bash
PUBLIC_ORIGIN=http://localhost:8088 WEB_PORT=8088 API_HOST_PORT=18080 docker compose -p mh26e2e up --build -d
cd web && npx playwright install chromium && E2E_BASE_URL=http://localhost:8088 npm run e2e
WEB_PORT=8088 API_HOST_PORT=18080 docker compose -p mh26e2e down -v
```

## Документация

Документация лежит в каталоге `docs/` и собирается mdBook. Каталоги `docs/book/` и `docs/export/` собираются заново, `docs/book/` в git не коммитят.

Сайт для просмотра:

```bash
cd docs && mdbook serve
```

mdBook ставится командой `cargo install mdbook` или пакетом системы. В образ API и в Compose он не входит.

Единый документ в форматах PDF и DOCX:

```bash
node scripts/docs/build.mjs
```

Сценарий собирает главы в порядке оглавления и создаёт файлы `docs/export/documentation.pdf` и `docs/export/documentation.docx`. Нужны Pandoc и Google Chrome.

Текст документации следует правилам `AGENTS.md`: без тире и стрелок, с буквой «ё», кавычки «ёлочки», десятичная запятая. Внутренние коды (версии моделей, идентификаторы полей, контрольные суммы) в пользовательских разделах не показываются.
