# Как менять код

Числа считают пакеты `api/internal/matching`, `api/internal/econ` и `api/internal/sim`. Интерфейс формулы не выдумывает. Сборка прогона симуляции из черновика живёт в `api/internal/simbuild`: базы она не трогает, один и тот же вход уходит в очередь заданий и в браузерное ядро.

Процесс API: `api/cmd/api`. То же ядро для браузера: `api/cmd/engine-wasm`, файлы отдаются с `/api/engine/`. Как собрать wasm локально, написано в README репозитория.

Запись проекта идёт только операциями `insert`, `set`, `delete`, `move`. Эталон применения: `api/internal/ops`. То же применение на клиенте: `web/src/store`. Отдельного PUT для содержимого проекта нет. Расчёт операцией не является: его считает Go.

HTTP-клиент интерфейса: `web/src/api`. Сгенерированные запросы к Postgres: `api/internal/db`, руками не правят. Загрузка каталога: `api/internal/importers`. Отчёты: `api/internal/exporters`. Очередь симуляции внутри процесса API: `api/internal/jobs` и `api/internal/simjobs`.

## Что нельзя разъехать

Расчёт при тех же снимке, каталоге, версии модели и зерне генератора даёт те же числа. На запуске пишется контрольная сумма каталога. Смена версии экономики или подбора делает сохранённый запуск устаревшим.

Если симуляция и экономика разошлись больше чем на 15%, в ответе есть флаг проверки. Прятать его нельзя.

Гостевые коммерческие вводы в Postgres не пишутся.

Импорт строки каталога идемпотентен по id решения.

Версия экономики сейчас `econ-v3`, константа `econ.ModelVersion`. В ADR 0004 она ещё названа econ-v2: смотрите константу. Событийная симуляция `sim-v2` (`sim.Version`). Проверка пропускной способности внутри расчёта остаётся `sim-v1` в `api/internal/sim/geom`.

Контракт HTTP: `api/openapi.yaml`. Почему нет PUT и как устроены снимки: [ADR 0001](adr/0001-snapshots-variants-jobs-events.md), [ADR 0003](adr/0003-operations-and-sync.md).

Комментарий экспортируемого пакета: одна фраза. Справку по символам не собираем.

## Новое поле проекта

Поле начинается в `contracts/ops/project.schema.json`. Затем из корня репозитория:

```bash
node scripts/gen-ops-schema.mjs
```

Скрипт копирует схему к читателям в Go и в `web/src/store` и обновляет сгенерированный TypeScript. Фикстура на это поле нужна в `api/internal/ops/fixtures_test.go`. Пока фикстуры нет, поле считается незакрытым.

## Новый маршрут

Обработчик и правка `api/openapi.yaml` идут в одном изменении. Поля ответа в Markdown не дублируют. Их держит `api/openapi.yaml`.

Ошибка текущего экспорта после правки черновика: HTTP 409, код `stale_result`.

## Новая переменная окружения

Чтение в `api/internal/config`. Имя и смысл в `.env.example` и в таблице README репозитория. Секрет в репозиторий не кладут.

## Тесты

```bash
cd api && go test ./...
```

Интеграционные тесты (очередь симуляций, права, гость, отчёты, миграции вверх и вниз) стартуют, если задан `TEST_DATABASE_URL`. Пользователю нужно право `CREATE DATABASE`. Каждый тест создаёт и удаляет свою базу. Команда и пример Postgres в README репозитория.

```bash
cd web && npm test && npm run lint && npm run build
```

Сквозные тесты гоняют Playwright на чистом compose-стеке. Там же в README: порты, `PUBLIC_ORIGIN` должен совпасть с адресом тестов, иначе API ответит `csrf`.

Книга собирается из этого каталога. Каталог `docs/book/` в git не коммитят.

```bash
cd docs && mdbook serve
```

mdBook ставится через `cargo install mdbook` или пакет системы. В образ API и в compose он не входит.
