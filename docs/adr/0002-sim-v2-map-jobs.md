# ADR 0002: sim-v2, карта склада и очередь заданий

Статус: принято
Дата: 2026-09-16

Уточняет ADR 0001 для этапов 22-26 сентября.

## Версии

- `sim-v1` переехал в `internal/sim/geom`. Он остается быстрой проверкой расхождения экономики и симуляции внутри `/calculate`. Гостевого `/api/guest/sim` больше нет: демо запускает sim-v2 в браузере. Результаты sim-v1 помечены `sim-v1`, а не `econ-v1`.
- `sim-v2` живет в `internal/sim`: событийное ядро, профили роботов в `internal/sim/profiles`.
- `calculation_runs.sim_version` расчета экономики остается `sim-v1`. Запуск симуляции пишет `sim-v2` и `kind = simulation`.
- Результат симуляции устаревший, если hash черновика отличается от hash запуска или версия `sim-v2` сменилась.

## Модель

- Задание перевозит груз от точки забора к точке доставки процесса. Точки задаются потоками `MapDocument.layers.flows`, а не `project_processes.point_ids`.
- Спрос в час = спрос в сутки / единиц в задании / активные часы суток x профиль часа. Активные часы берутся из окна смены.
- Профили AMR и паллетного робота различаются действиями (подъем под грузом или вилы с подъемом на ярус), габаритами, скоростью с грузом и потреблением энергии. Значения каталога переопределяют значения класса, подставленные значения перечисляются в допущениях.
- AMR с грузоподъемностью от 400 кг возит паллеты по полу, но не ставит их в стеллаж. Размещение и отгрузка из ячеек выполняет паллетный робот.
- Общие ресурсы: док (точки), узкий участок (ребра), зарядка (точки). Очередь к ресурсу FIFO.
- Однополосный участок: ширина меньше `2 x ширина + 1.5 x зазор` самого широкого класса. Цепочки однополосных ребер без развилок становятся ресурсом вместимостью 1. Робот, стоящий в тупике участка, держит его.
- Ширина ребра = заявленная ширина, ограниченная свободным коридором до препятствий и стен рабочей области. Ребро уже `ширина + зазор` класса непроходимо для него, маршрут идет в объезд.
- Диспетчеризация: `fifo`, `nearest`, `sla_priority`. SLA: ожидание до назначения и полный цикл.
- Вероятностный режим: пуассоновский поток, логнормальные длительности, до 30 повторов с seed `seed + i`. Детерминированный режим: один прогон.
- Итог: медиана, min, max, p10, p90. SLA выполнен, если p90 доли нарушений не выше допуска (5% по умолчанию).
- Узкое место: сначала насыщенный ресурс (загрузка от 85% или средняя очередь от половины вместимости), затем флот, если роботы свободны меньше 10% времени.

## Журнал

- Хранится один повтор, ближайший к медиане нарушений и производительности. Он перезапускается с записью, метрики совпадают с прогоном без записи.
- Формат `sim-log-v1`: заголовок со сценой в метрах, графом, роботами и ресурсами; события `sim-event-v1`; контрольные состояния каждые 60 с.
- Журнал сжат gzip и лежит в `simulation_artifacts`. Срок хранения 90 дней, закрепленный журнал не удаляется. Лимит 400 000 событий, дальше `truncated`.

## Очередь заданий

- Таблица `simulation_jobs`, захват `FOR UPDATE SKIP LOCKED`, встроенный пул в процессе API (`SIM_WORKERS`).
- Heartbeat раз в секунду пишет прогресс и проверяет отмену. Зависшее задание без heartbeat 30 с возвращается в очередь или падает после `max_attempts`.
- При остановке API текущее задание возвращается в очередь без списания попытки.
- Итог, повторы, журнал и статус `succeeded` пишутся одной транзакцией.
- Одно активное задание на проект, `SIM_MAX_ACTIVE_PER_USER` на пользователя.

## Карта

- Координаты объектов в пикселях страницы, метры = пиксели x `meters_per_px`. Исходный план не отправляется на сервер.
- Черновик карты сохраняется даже с ошибками, ошибки пишутся в документ. Запуск симуляции с ошибками карты запрещен.
- Без карты проекта используется шаблон склада 84 x 52 м, уровень подтвержденности `preliminary` и предупреждение. С картой проекта уровень `configured`.

## Симуляция в браузере

- Сборка запуска (`JobConfig`, `Build`, шаблон и проверка карты, `Summary`) живёт в `internal/simbuild`, без базы и HTTP (это проверяет `deps_test.go`). Очередь заданий (`internal/simjobs`) и браузерное ядро (`api/cmd/engine-wasm`) строят запуск одним кодом. Флот берётся из нейтральной карты `Robots`, её даёт `simbuild.RobotsOf(engine.Catalog)`.
- Ядро в браузере отвечает `simulateMap`, `checkMap`, `mapTemplate` и `draftHash`. Запуск получает каталог и записи проекта (`collections`), возвращает сводку и журнал одного повтора. Сводка та же, что у серверного запуска, кроме `finished_at` и `duration_ms`; совпадение с нативной сборкой держит `contracts/engine/reference.json`.
- Запуски демо лежат в IndexedDB `robots-demo-runs`: пять последних на демо, журнал отдельно от сводки. Запуск устарел, если хеш записей демо теперь другой (`draftHash`). Запуск идёт по одному; отмена останавливает рабочий поток симуляции, расчёт живёт в другом потоке.
- Демо-склад собран заранее: `web/src/guest/demo-warehouse.json`, его пишет `go test ./internal/simbuild -run TestDemoWarehouse -update`. Карта 84 x 52 м (шаблон `simbuild.Template`) и три варианта с роботами из каталога. Спрос равен минимуму схемы: на четырёх доках карты проходит около 500 паллет в сутки, при 1000 любой вариант упирается в них. Число роботов подобрано симуляцией. Тест требует вердикт `pass` у каждого варианта и расчёт без флага сверки; если каталог или значения по умолчанию изменились, он сообщает, что файл устарел.

## Не сделано

- Автоматическое построение графа, встречное движение внутри двухполосного ребра, лифты и двери.
- Отказы и обслуживание: нет данных, модель работает без отказов.
- Перенос производительности из симуляции в экономику (`apply-simulation-throughput`) остается на 27-28 сентября.
