# Программный интерфейс

Полное описание методов, параметров и схем ответов находится в файле `api/openapi.yaml` (OpenAPI 3.0.3). Этот раздел описывает общие правила и группы методов.

## Общие правила

- Обмен идёт в формате JSON. Исключения: выгрузка файлов, изображения роботов и файлы браузерного ядра.
- Адрес API в составе Compose: `http://localhost:8080`. Через веб-сервер те же методы доступны по префиксу `/api`.
- Аутентификация построена на cookie сессии. При `COOKIE_SECURE=true` cookie называется `__Host-session`, иначе `session`.
- Изменяющие запросы должны приходить со страницы приложения: заголовок `Origin` сверяется с `PUBLIC_ORIGIN`. При несовпадении API отвечает ошибкой `csrf`.
- Содержимое проекта меняется только операциями: `POST /api/projects/{id}/transactions`. Методов `PUT` для содержимого проекта нет.
- Расчёт, подбор и симуляция детерминированы при одинаковом снимке проекта, каталоге, версии модели и зерне генератора.

## Формат ошибки

Ошибки возвращаются в одной форме:

```json
{
  "error": "Текст для человека: что произошло и что делать",
  "code": "stale_result",
  "request_id": "..."
}
```

| Код | Когда возвращается |
|---|---|
| `csrf` | Запрос пришёл не со страницы приложения или страница устарела |
| `forbidden` | Не хватает прав на проект или на действие |
| `not_found` | Такого адреса или ресурса нет |
| `invalid_value` | Значение не прошло проверку схемы |
| `stale_result` | Черновик проекта изменился после расчёта, текущий результат выгрузить нельзя (HTTP 409) |
| `api_unavailable` | Веб-сервер не получил ответа от API (HTTP 503) |

## Группы методов

| Группа | Основные адреса | Назначение |
|---|---|---|
| Служебные | `/health`, `/version` | Проверка работы и версии моделей |
| Каталог | `/api/solutions`, `/api/catalog/dictionaries`, `/api/catalog/bundle` | Список и карточки роботов, справочники, полный набор для демо |
| Типы объектов | `/api/object-types`, `/api/object-types/{type}/schema` | Типы объектов и схемы их параметров |
| Гость | `/api/guest/calculate`, `/api/guest/match`, `/api/guest/export` | Расчёт, подбор и выгрузка без сохранения |
| Учётные записи | `/api/auth/*` | Регистрация, вход, выход, подтверждение почты, сброс пароля, сессии, приглашения |
| Проекты | `/api/projects`, `/api/projects/{id}`, `/copy`, `/restore`, `/purge`, `/trash`, `/import` | Создание, копирование, корзина, импорт снимка |
| Содержимое проекта | `/transactions`, `/snapshot`, `/operations`, `/events`, `/presence` | Операции, снимок, журнал операций, поток событий, присутствие |
| Расчёт | `/api/projects/{id}/calculate`, `/match`, `/calculations`, `/api/calculations/{runId}` | Расчёт, подбор, сохранённые запуски |
| Отчёты | `/api/projects/{id}/export`, `/api/calculations/{runId}/export` | Выгрузка PDF и XLSX |
| Участники | `/api/projects/{id}/members` | Роли в проекте |
| Карта и симуляция | `/map/validate`, `/map/template`, `/simulations`, `/api/simulation-jobs/{jobId}`, `/api/simulation-runs/{runId}` | Проверка карты, задания, результаты, журналы событий |
| Нормативы | `/api/norms`, `/api/admin/norms` | Чтение и изменение нормативов |
| Администрирование | `/api/admin/solutions`, `/api/admin/catalog/*`, `/api/admin/invitations`, `/api/admin/audit` | Каталог, загрузка таблиц, приглашения, журнал |

Ответ на выгрузку отчёта содержит заголовки `X-Run-Id` и `X-Input-Hash`. По ним отчёт связывается с запуском.

## Интеграции

Программные интерфейсы для импорта данных:

- параметры объекта: `POST /api/projects/import` и операции проекта;
- каталог: `/api/admin/catalog/imports` (предпросмотр, подтверждение, список ошибок);
- нормативы: `/api/admin/norms`.

Коннекторов к WMS, ERP, 1С и системам мониторинга в поставке нет. Возможные интеграции описаны в разделе [Ограничения и план](../guide/10-limits.md).
