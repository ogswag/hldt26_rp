# Подбор роботов

Подбор проверяет каждую модель из каталога на соответствие параметрам объекта. Для каждой модели он выдаёт вердикт, оценку и объяснение: какие проверки пройдены, какие нет и каких данных не хватает.

Подбор выполняется на вкладке **Роботы**. Параметры объекта берутся из вкладки **Объект**.

## Вердикты

| Вердикт | Значение | Что можно сделать |
|---|---|---|
| Рекомендован | Все ключевые проверки пройдены, тип объекта совпадает | Выбрать робота в вариант |
| Требует проверки | Нет части данных, чтобы подтвердить соответствие: например, в технических характеристиках пусто ключевое поле | Выбрать робота в вариант: расчёт покажет предупреждение |
| Не подходит | Хотя бы одно жёсткое ограничение нарушено | Добавить в вариант вручную: платформа покажет предупреждение и риск |

Платформа не скрывает исключённых роботов. Пользователь может добавить такую модель в сравнение осознанно. Расчёт при этом учитывает риск, а страница «Итог» показывает его.

## Проверки

Проверки делятся на жёсткие и мягкие. Нарушение жёсткой проверки исключает робота. Мягкая проверка робота не исключает: она снижает оценку, добавляет замечание и переводит вердикт в «Требует проверки».

### Жёсткие проверки

| Проверка | Условие исключения |
|---|---|
| Проезд | Ширина робота или его минимальный проезд больше проезда на объекте |
| Грузоподъёмность | Грузоподъёмность меньше массы единицы груза на объекте |
| Температура | Температура на объекте вне рабочего диапазона робота |
| Высота потолков | Высота робота больше высоты потолков |
| Нагрузка на пол | Давление робота на пол больше допустимой нагрузки |
| Лифт | Масса робота больше грузоподъёмности лифта |
| Дверные проёмы | Ширина робота больше проёма |
| Разворот | Круг по диагонали корпуса больше свободного места для разворота |
| Тип объекта | В карточке робота не указан подходящий тип объекта или его класс не относится к объекту (например, морская техника) |

### Мягкие проверки

| Проверка | Что оценивается |
|---|---|
| Задачи | У модели нет возможности, которая нужна для выбранной задачи объекта |
| Тяжёлая логистика | Грузоподъёмность меньше массы паллеты или тележки: модель годится только для лёгкой доставки |
| Цена | Цена модели не выше бюджета CAPEX из параметров объекта |
| Полнота данных | Доля заполненных ключевых полей технических характеристик |

Если для проверки не хватает данных, платформа не исключает робота, а присваивает вердикт «Требует проверки» и объясняет, какое поле нужно уточнить.

## Оценка

Оценка это число от 0 до 1. Она складывается из четырёх частей с весами:

| Часть | Вес | Что учитывается |
|---|---|---|
| Соответствие | 40% | Запас по габаритам и условиям эксплуатации |
| Процесс | 25% | Совпадение процесса модели с типом объекта |
| Полнота данных | 20% | Доля заполненных ключевых характеристик |
| Ценовой пояс | 15% | Цена относительно бюджета CAPEX |

Оценка помогает упорядочить роботов внутри одного вердикта. Части оценки и веса отображаются в разборе робота.

## Порядок в списке

Порядок списка определяется двумя правилами.

1. Сначала идут роботы с вердиктом «Рекомендован», затем «Требует проверки», затем «Не подходит».
2. Внутри одного вердикта роботы, для которых рассчитана окупаемость, идут первыми, по возрастанию срока окупаемости. Остальные располагаются по оценке.

Окупаемость для списка рассчитывается для случая «этот робот один в варианте». Кнопка **Выбрать** записывает в вариант именно этот случай, поэтому предложение на странице «Роботы» совпадает с итогом расчёта.

## Как читать объяснение

Для каждого робота платформа показывает разбор:

- **Причины.** Короткий список того, почему вердикт именно такой.
- **Жёсткие проверки.** Что пройдено и что нарушено, со значениями на объекте и у робота.
- **Мягкие замечания.** Что снижает оценку.
- **Недостающие данные.** Какие поля нужно уточнить в каталоге.
- **Источник.** Ссылка на источник характеристики и уровень подтверждённости.

Такой разбор позволяет понять, какое именно условие исключило модель, и решить, что менять: объект, каталог или выбранную модель.
