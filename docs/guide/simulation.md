# Симуляция

Симуляция имитирует работу роботов на плане склада. Она проверяет, что производительность флота из экономического расчёта достижима на конкретной карте, и показывает загрузку оборудования, простои и узкие места.

Симуляция на карте есть только у склада. Для аэропорта и больницы платформа выполняет быструю проверку без карты по каждой позиции флота.

## Как работает модель

Модель событийная: время идёт от события к событию, а не равными шагами.

### Задания и спрос

Задание состоит в том, чтобы перевезти груз от точки забора к точке доставки. Точки берутся из потоков на карте. Спрос в час считается так:

```text
спрос в час = спрос в сутки / единиц в задании / активные часы суток * профиль часа
```

Активные часы определяются окном смены.

### Роботы

Профили роботов различаются действиями (подъём под грузом или вилы с подъёмом на ярус), габаритами, скоростью с грузом и потреблением энергии. Значения из каталога переопределяют значения класса. Подставленные значения перечислены в допущениях запуска.

Робот класса AMR грузоподъёмностью от 400 кг возит паллеты по полу, но не ставит их в стеллаж. Размещение и отгрузку из ячеек выполняет паллетный робот.

### Общие ресурсы

Роботы делят между собой док, узкий участок и зарядную станцию. К каждому ресурсу выстраивается очередь по порядку прихода.

Узкий участок: однополосный отрезок маршрута, у которого ширина меньше `2 * ширина + 1,5 * зазор` самого широкого класса роботов. Цепочка таких отрезков без развилок работает как ресурс вместимостью 1. Робот, остановившийся в тупике участка, удерживает его.

Маршрут идёт в обход участков, которые уже, чем `ширина + зазор` робота.

### Диспетчеризация

Задания назначаются по одному из трёх правил:

- по порядку поступления;
- ближайшему свободному роботу;
- по приоритету соблюдения SLA.

SLA оценивается по времени ожидания до назначения и по полному циклу задания.

## Режимы прогона

| Режим | Как работает | Что показывает |
|---|---|---|
| Детерминированный | Один прогон | Одно значение каждого показателя |
| Вероятностный | До 30 повторов: пуассоновский поток заданий, логнормальные длительности | Медиану, минимум, максимум, 10-й и 90-й процентили |

SLA считается выполненным, если 90-й процентиль доли нарушений не выше допуска. Допуск по умолчанию 5%.

## Узкие места

Платформа ищет узкое место в два шага:

1. Сначала проверяет ресурсы. Ресурс насыщен, если его загрузка не меньше 85% или средняя очередь не меньше половины вместимости.
2. Если насыщенных ресурсов нет, проверяет флот. Флот считается узким местом, если роботы свободны меньше 10% времени.

## Сверка с экономикой

После прогона платформа сравнивает производительность из симуляции с той, что заложена в экономику. Если расхождение больше 15%, результат помечается предупреждением. Оно остаётся, пока причина не устранена.

Сверка привязана к варианту. Правка одного варианта не делает устаревшей сверку другого.

## Подбор числа роботов

На странице **Симуляция** кнопка **Подобрать** ищет наименьшее число роботов, при котором покрытие спроса не меньше 85% и SLA укладывается в допуск. Поиск идёт прогонами симуляции.

Кнопка **Взять N в вариант** записывает найденное число в вариант одной операцией. Число попадает в тот вариант, для которого шёл подбор. После этого страница «Итог» пересчитывается, а сверка для этого варианта считается действующей. Пока число не записано, прогон подбора сверкой не служит.

Если ни один размер не проходит проверку, платформа число не предлагает и кнопка **Взять N в вариант** не показывается. Проверьте карту и спрос процессов, затем запустите подбор снова.

## Карта склада

На карте заданы зоны, проезды, препятствия, точки забора и доставки, зарядные станции и потоки. Карту можно нарисовать в редакторе (**Объект / Карта**) или загрузить из файла плана.

- Координаты хранятся в пикселях страницы, метры получаются умножением на масштаб. Исходный файл плана на сервер не отправляется.
- Черновик карты сохраняется даже с ошибками, ошибки записываются в документ. Запуск симуляции с ошибками карты запрещён.
- Если у проекта нет своей карты, используется шаблон склада 84 x 52 м. Тогда результат получает уровень подтверждённости «предварительный» и предупреждение. С картой проекта уровень «настроенный».

## Запуск симуляции

Симуляция проекта выполняется заданием в очереди. Задания обрабатывает тот же процесс API. Пользователь видит статус задания и может отменить его или повторить.

- Не больше трёх активных заданий на пользователя и одного на проект.
- Задание, которое 30 секунд не обновляло статус, возвращается в очередь. Если попытки закончились, оно завершается с ошибкой.
- Предел времени одного задания по умолчанию 10 минут. Значения настраиваются, см. [Переменные окружения](../reference/env.md).

Демо считают симуляцию в браузере. Результаты хранятся там же: пять последних запусков на каждое демо.

## Воспроизведение

| Элемент | Назначение |
|---|---|
| **Пуск**, **Пауза**, **Сначала** | Управление воспроизведением |
| **Скорость** | От 1x до 600x |
| Выбор варианта | Какой вариант показывать |
| **Сохранить кадр** | Сохраняет текущий кадр в файл PNG |
| **Показатели CSV** | Сохраняет показатели запуска в файл CSV |

Воспроизводится один повтор, ближайший к медиане нарушений и производительности. Его журнал хранится в сжатом виде 90 дней, закреплённый журнал не удаляется. В журнал попадает не больше 400 000 событий, остальные отбрасываются, и запуск получает пометку об усечении.

## Что не моделируется

- Автоматическое построение графа маршрутов, встречное движение внутри двухполосного участка, лифты и двери.
- Отказы и обслуживание роботов: данных для них нет, модель работает без отказов.

Подробности реализации приведены в [ADR 0002](../adr/0002-sim-v2-map-jobs.md).
