# Архитектура

Платформа состоит из одного исполняемого файла API на Go, статического веб-приложения на React и базы данных Postgres. Расчёт, подбор и симуляция выполняются одним ядром, которое запускается и на сервере, и в браузере.

## Компоненты

```text
Браузер
  ├── Приложение React (статические файлы)
  └── Браузерное ядро engine.wasm (расчёт, подбор, симуляция)
        │  HTTP, JSON, события SSE
        ▼
Веб-сервер nginx ── статические файлы приложения
        │  запросы /api, /health, /version
        ▼
Сервер API на Go ── очередь заданий симуляции (в том же процессе)
        │  SQL
        ▼
База данных Postgres 18
```

| Компонент | Технологии | Назначение |
|---|---|---|
| Сервер API | Go, chi, pgx, sqlc, excelize | Учётные записи, проекты, каталог, расчёт, очередь симуляций, отчёты |
| Веб-приложение | React, Vite, TypeScript, TanStack Query, Konva | Интерфейс, редактор карты, воспроизведение симуляции |
| Браузерное ядро | Go, собранный в WebAssembly | Расчёт, проверка карты и симуляция демо без обращения к серверу |
| База данных | Postgres 18 | Проекты, запуски, каталог, сессии, журналы |
| Веб-сервер | nginx | Раздача приложения и проксирование запросов к API |

Очередь заданий симуляции работает внутри процесса API. Отдельные брокеры сообщений и внешние воркеры не нужны.

## Единое ядро расчёта

Пакеты `matching`, `econ` и `sim` реализуют подбор, экономику и симуляцию. Сервер и браузер вызывают один и тот же код: сервер собирает его в обычный исполняемый файл, браузер получает файл `engine.wasm` по адресу `/api/engine/`.

Благодаря этому демо-проекты гостя считаются в браузере и дают те же числа, что и сервер. Совпадение проверяется контрольным файлом `contracts/engine/reference.json`.

Интерфейс не содержит собственных формул. Формулы для страницы «Формулы и источники» тоже отдаёт ядро.

## Операции над проектом

Данные проекта меняются только операциями: запросом `POST /api/projects/{id}/transactions`. Операция бывает четырёх видов: вставка, установка значения, удаление и перемещение записи. Отдельных запросов `PUT` для содержимого проекта нет.

У такого подхода три следствия:

- несколько редакторов работают над проектом одновременно, а правка, которую сервер не принял из-за конфликта, не теряется, а попадает в список «Не применено» с возможностью восстановить;
- правки можно отменять и повторять в пределах сеанса;
- клиент хранит правки в очереди в браузере и отправляет их при появлении связи.

Расчёт операцией не является: его выполняет сервер по снимку проекта. Подробности см. в [ADR 0003](../adr/0003-operations-and-sync.md).

## Модель данных

Основные таблицы Postgres сгруппированы по назначению.

| Группа | Таблицы | Содержимое |
|---|---|---|
| Пользователи | `users`, `sessions`, `email_tokens`, `email_outbox`, `invitations` | Учётные записи, сессии, письма и приглашения |
| Проекты | `projects`, `project_drafts`, `project_operations`, `project_members`, `project_processes`, `shared_cost_items` | Проект, черновик, журнал операций, участники и роли |
| Варианты | `solution_variants`, `variant_fleet_items`, `financing_scenarios`, `assumption_sets` | Состав флота, способы оплаты, наборы допущений |
| Запуски | `project_versions`, `calculation_runs`, `calculation_results` | Неизменяемые снимки проекта и результаты расчётов |
| Симуляция | `simulation_jobs`, `simulation_replications`, `simulation_artifacts` | Очередь заданий, повторы прогонов, сжатые журналы событий |
| Каталог | `solutions`, `solution_specs`, `solution_images`, `catalog_imports`, `catalog_exports` | Роботы, технические характеристики, изображения, загрузки |
| Нормативы и журнал | `calc_norms`, `audit_events` | Нормативы расчёта, журнал действий |

Схема хранится в миграциях `api/migrations`. Миграции применяются автоматически при старте API.

## Воспроизводимость результатов

Каждый расчёт и каждая симуляция сохраняются как неизменяемый запуск. Запуск содержит:

- снимок входных данных проекта и его контрольную сумму `input_hash` (SHA-256 канонического JSON);
- контрольную сумму каталога `catalog_content_sha256` и нормативов `norms_sha256`;
- версии моделей: подбор, экономика (`econ-v3`), симуляция (`sim-v2`);
- зерно генератора случайных чисел (seed);
- уровень подтверждённости: предварительный, настроенный, калиброванный или подтверждённый.

Если контрольная сумма черновика не совпадает с контрольной суммой запуска, результат считается устаревшим: выгрузить его нельзя. Исторический запуск выгружается с пометкой о том, что черновик изменился.

Каталог живой: правка администратора попадает в следующий расчёт. Уже сохранённый запуск остаётся на том каталоге, с которым его посчитали.

## Безопасность

- Пароли хранятся в виде хэшей bcrypt. Стоимость хэширования задаёт переменная `BCRYPT_COST`.
- Сессия хранится в cookie `__Host-session` при включённой защите (`COOKIE_SECURE=true`). Срок сессии ограничен временем простоя и предельным сроком.
- Изменяющие запросы проверяются по заголовку `Origin`. Значение должно совпадать с `PUBLIC_ORIGIN`, иначе API отвечает ошибкой `csrf`.
- Доступ к проекту определяется ролью в нём: владелец, редактор или читатель. Проекты разных пользователей изолированы.
- Вкладка «Админ» и запросы `/api/admin/*` доступны только администратору.
- Коммерческие данные гостя в базу и журналы не пишутся.
- Шифрование канала обеспечивает внешний прокси: приложение рассчитано на работу по HTTPS, но в составе `docker-compose.yml` TLS не терминируется.

## События в реальном времени

Сервер передаёт события проекта по протоколу SSE (`GET /api/projects/{id}/events`): новые операции, присутствие участников, завершённые запуски, изменение доступа. Благодаря этому участники видят правки друг друга без перезагрузки страницы.

## Расширяемость

Платформа рассчитана на добавление новых объектов и решений без переработки ядра:

- схема параметров типа объекта описывается отдельным файлом в `api/internal/objects` (склад, аэропорт, больница);
- каталог загружается таблицей, новые роботы и поля добавляются без изменения кода;
- нормативы расчёта хранятся в базе и правятся в интерфейсе администратора;
- контракты данных описаны схемами JSON в каталоге `contracts/`, программный интерфейс описан файлом `api/openapi.yaml`.

Редактора справочников в интерфейсе нет: новый тип объекта добавляется в код вместе с правилами расчёта.

## Структура репозитория

| Каталог | Содержимое |
|---|---|
| `api/` | Сервер API на Go, миграции, спецификация `openapi.yaml` |
| `api/cmd/api` | Точка входа сервера |
| `api/cmd/engine-wasm` | Точка входа браузерного ядра |
| `api/internal/` | Пакеты: `matching`, `econ`, `sim`, `simbuild`, `simjobs`, `ops`, `exporters`, `importers`, `auth`, `objects` и другие |
| `web/` | Веб-приложение на React |
| `contracts/` | Схемы JSON и эталонные данные ядра |
| `data/` | Каталог `catalog.csv` и технические характеристики `seeds/robot_specs.json` |
| `docs/` | Документация |
| `scripts/` | Сценарии сборки и проверок |
