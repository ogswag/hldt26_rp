# Развёртывание

Платформа состоит из трёх контейнеров: базы данных Postgres, сервера API и веб-сервера со статическим приложением. Контейнеры описаны в файле `docker-compose.yml` в корне репозитория.

## Требования

| Компонент | Требование |
|---|---|
| Docker и Docker Compose | Docker Engine или Docker Desktop с плагином Compose версии 2 |
| Порты на хосте | 80 (интерфейс) и 8080 (API); значения меняются переменными `WEB_PORT` и `API_HOST_PORT` |
| Место на диске | около 1 ГБ для образов и тома базы данных |
| Доступ в интернет | нужен только при первой сборке образов |

Для запуска в контейнерах устанавливать Go, Node.js и Postgres не требуется.

## Запуск

1. Клонируйте репозиторий и перейдите в его корень.
2. Выполните команду:

   ```bash
   docker compose up --build
   ```

3. Дождитесь сообщения `listen` в журнале сервера API. При первом запуске API применяет миграции, загружает каталог из файла `data/catalog.csv` и создаёт демонстрационные учётные записи.
4. Откройте в браузере адрес http://localhost.

Порты меняются так:

```bash
WEB_PORT=8088 API_HOST_PORT=18080 docker compose up --build
```

## Проверка работы

1. Откройте http://localhost:8080/health. Ответ с кодом 200 означает, что процесс API работает.
2. Откройте http://localhost и нажмите **Демо Склад**. Должна открыться страница «Объект» с заполненными параметрами.
3. Перейдите на вкладку **Расчёт**. Должна открыться страница «Итог» с таблицей из трёх сценариев.

Если каталог пуст, посев данных не прошёл. Выполните команды из раздела [Сброс данных](#сброс-данных) и запустите платформу снова.

## Демонстрационные учётные записи

Учётные записи создаются при старте API, если записей с такими адресами ещё нет.

| Роль | Адрес электронной почты | Пароль |
|---|---|---|
| Пользователь | `user@demo.local` | `demo-user` |
| Администратор | `admin@demo.local` | `demo-admin` |

> **Важно.** Смените демонстрационные пароли перед любой публикацией платформы в сети. Порядок описан в разделе [Сопровождение](../operations.md).

Гостю вход не нужен: демо-проекты «Демо Склад», «Демо Аэропорт» и «Демо Больница» открываются в браузере без учётной записи.

## Сброс данных

Команда ниже удаляет том базы данных. Вместе с ним пропадают все проекты, запуски и учётные записи.

```bash
docker compose down -v
```

При следующем запуске платформа заново загрузит каталог и создаст демонстрационные учётные записи. Не используйте параметр `-v` на стенде, данные которого нужно сохранить.

## Запуск без Docker

Этот способ нужен разработчикам. Потребуются Postgres 18, Go и Node.js.

1. Создайте пустую базу данных и задайте переменные окружения. Пример значений приведён в файле `.env.example`. Для локальной работы установите `COOKIE_SECURE=false` и `PUBLIC_ORIGIN=http://localhost:5173`.
2. Запустите сервер API:

   ```bash
   cd api && go run ./cmd/api
   ```

3. Запустите веб-приложение в другом окне терминала:

   ```bash
   cd web && npm install && npm run dev
   ```

   Vite передаёт запросы `/api` серверу API, поэтому браузер видит один адрес.

4. Соберите браузерное ядро расчёта, иначе проверка карты и симуляция демо-склада не заработают:

   ```bash
   cd api
   GOOS=js GOARCH=wasm go build -o <каталог>/engine.wasm ./cmd/engine-wasm
   cp "$(go env GOROOT)/lib/wasm/wasm_exec.js" <каталог>/
   ```

   Затем задайте `ENGINE_DIR=<каталог>` и перезапустите API.

## Статическая демонстрационная сборка

Демонстрационная сборка работает без сервера: приложение, браузерное ядро и справочные данные лежат в одном каталоге. Такую сборку можно разместить в любом хранилище статических файлов.

1. Запустите платформу командой `docker compose up -d --wait`.
2. Выполните сценарий сборки:

   ```bash
   scripts/ci/build-demo.sh
   ```

Результат появится в каталоге `web/dist`. Демонстрационная сборка ничего не сохраняет, в ней нет учётных записей и идентификаторов запусков.
